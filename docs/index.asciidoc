== Logstash STANAG 4778 Filter Plugin

The `stanag4778` filter parses and validates NATO STANAG 4778 Binding Data Objects (BDOs) in both XML (ADatP-4778 / ADatP-4778.2) and JSON (ADatP-4778.7) formats.

It supports:
* Parsing encapsulating, embedded, and detached Binding Data Objects (BDOs).
* Cryptographic signature verification using XMLDSIG (RSA, ECDSA, HMAC) compliant with ADatP-4778.2 profile rules.
* Cryptographic signature verification using JSON Web Signatures (JWS Compact Serialization) compliant with ADatP-4778.7.
* Fail-closed trust decision model: public keys or HMAC secrets transmitted inside message headers or bodies are never trusted unless they match pre-configured trust material.
* Extraction of STANAG 4774 Confidentiality Metadata Labels (both XML `slab:originatorConfidentialityLabel` and JSON `ocl`/`acl`).
* Evaluation of same-document references using JSON Pointer (RFC 6901), JSONPath (RFC 9535), and JMESPath with RFC 8785 JSON Canonicalization Scheme (JCS).
* Hardened HTTPS fetching for detached references against an explicit hostname allowlist, with SSRF protection (loopback/private IP blocking and manual redirect re-validation).
* Java Cryptography Architecture (JCA) integration with no external native C extensions or vendored JAR dependencies.

[id="plugins-{type}s-{plugin}-trust-model"]
=== Trust Model

To protect against forged signatures, the filter enforces a strict **fail-closed trust model**:
1. **Never Trust Embedded Keys Directly**: An attacker can sign a payload with their own key and place that key in the JWS `jwk` header or the XMLDSIG `<ds:KeyValue>` element. The filter will reject any embedded key unless it matches a pre-configured trusted certificate, a key in `jwks_path`, or a key in `hmac_keys`.
2. **Symmetric Keys**: Symmetric `oct` JWKs in JWS headers are explicitly prohibited. HMAC secrets must be configured via `hmac_keys` on the verifier side.
3. **Certificate Policy**: Signer certificates must be within their valid lifetime and have digital signature capabilities. Optional subject name whitelisting (`allowed_signer_subjects`), Extended Key Usage requirements (`required_extended_key_usage`), and PKIX revocation checking (`revocation_mode`) can be enforced.

[id="plugins-{type}s-{plugin}-example"]
=== Example: Verifying XML BDOs with Pinned Certificates

[source,ruby]
----------------------------------
filter {
  stanag4778 {
    source => "message"
    target => "stanag"
    trusted_certificates => ["/etc/pki/nato-originator.pem"]
    require_signature => true
    strict_profile => true
  }
}
----------------------------------

=== Example: Verifying JSON BDOs with HMAC Secrets

[source,ruby]
----------------------------------
filter {
  stanag4778 {
    source => "message"
    target => "stanag"
    hmac_keys => {
      "key-01" => "${STANAG_HMAC_SECRET}"
    }
    require_signature => true
  }
}
----------------------------------

==== `source`
* Value type is <<string,string>>
* Default value is `nil`
* This setting is required.

Field containing the XML document or JSON object to parse and verify.

==== `target`
* Value type is <<string,string>>
* Default value is `"stanag4778"`

The target field where verification details, signature status, and extracted labels will be written.

==== `format`
* Value type is <<string,string>>
* Permitted values: `"auto"`, `"xml"`, `"json"`
* Default value is `"auto"`

Input syntax detection. `"auto"` sniffs the payload format based on opening characters (`<` vs `{`/`[`).

==== `require_signature`
* Value type is <<boolean,boolean>>
* Default value is `true`

When true, unsigned BDOs (or JWS with `alg: "none"`) are marked `valid: false` and tagged with `_stanag4778_unsigned` and `_stanag4778_invalid`.

==== `strict_profile`
* Value type is <<boolean,boolean>>
* Default value is `true`

Enforces strict compliance with NATO ADatP-4778.2 and ADatP-4778.7 profile rules:
* Prohibits legacy weak algorithms (`sha1`, `md5`, `dsa-sha1`, etc.).
* Enforces required headers (`cty: "vnd.nato.bindingdataobject+json"`).
* If `crit` is present, enforces that it is non-empty, all listed parameters exist in the header, and all parameters belong to recognized STANAG 4778.7 parameters.
* Enforces presence of XML `<wsu:TimeStamp>` with `<wsu:Created>`.
* Enforces enveloped-BDO XPath transforms for embedded XML BDOs.

==== `ssl_certificate_authorities`
* Value type is <<path,path>>
* Default value is `nil`

Path to a PEM bundle of trusted Root and Intermediate Certificate Authorities for PKIX certificate chain validation.

==== `trusted_certificates`
* Value type is <<array,array>>
* Default value is `[]`

List of paths to pinned X.509 signer certificates in PEM format.

==== `revocation_mode`
* Value type is <<string,string>>
* Permitted values: `"none"`, `"crl"`, `"ocsp"`
* Default value is `"none"`

Enables PKIX revocation checking using CRLs or OCSP responders. When set to `"none"`, certificate revocation is not checked over the network, and the event records `"revocation_checked" => false`.

==== `required_extended_key_usage`
* Value type is <<array,array>>
* Default value is `[]`

Array of Extended Key Usage (EKU) OIDs required to be present on the signer certificate (e.g. `["1.3.6.1.5.5.7.3.3"]` for Code/Content Signing).

==== `allowed_signer_subjects`
* Value type is <<array,array>>
* Default value is `[]`

List of regular expressions matched against the signer certificate subject Distinguished Name (DN).

==== `hmac_keys`
* Value type is <<hash,hash>>
* Default value is `{}`

Mapping of HMAC Key Identifier (`kid` or `KeyName`) to secret strings.

==== `fetch_external_references`
* Value type is <<boolean,boolean>>
* Default value is `false`

When enabled, detached references (`DataReference` or `MetadataReference`) with external HTTPS URLs are retrieved and verified against the declared digest hash.

==== `external_reference_allowlist`
* Value type is <<array,array>>
* Default value is `[]`

Required when `fetch_external_references` is true. Specifies exact hostnames or wildcard patterns (e.g., `*.nato.int` matching subdomains) permitted for external fetching.

[NOTE]
====
**DNS Rebinding Considerations**: The filter verifies resolved IP addresses prior to initiating HTTP requests to block loopback and private ranges. However, in environments subject to active DNS rebinding adversaries, configuring local forward proxies or pin-point firewall egress controls is recommended.
====

[id="plugins-{type}s-{plugin}-tags"]
=== Tags Added on Failure

* `_stanag4778_parse_failure`: The payload could not be parsed as valid XML or JSON, or an XML external entity (XXE) attempt was rejected.
* `_stanag4778_invalid`: Cryptographic signature verification failed, a reference hash mismatched, or an ADatP profile constraint was violated.
* `_stanag4778_unsigned`: The BDO is unsigned or has `alg: "none"` while `require_signature => true`.
* `_stanag4778_unresolved_reference`: A detached external reference could not be fetched (disabled, host not in allowlist, network timeout, or private IP blocked).
